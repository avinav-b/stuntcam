# Third-party notices

stuntcam is Apache-2.0 ([LICENSE](LICENSE)). This file lists every file or fragment in the tree that isn't ours, with
where it came from and under which licence. Our own source files
carry an `SPDX-License-Identifier: Apache-2.0` line, checked by `tools/spdx-check.sh`; the files below don't, and that
script skips the third-party source files among them.

Where the repo doesn't record an upstream commit SHA or version, this file says so ("not recorded — TODO") rather than
guess one. The scope is the shipped tree: `build.sh`, `engine/`, `cli/`, `canary/`, `scripts/`, `tools/`, `fixtures/`,
`restore-rules/`.

The npm package and Homebrew tarball (`scripts/package.sh`) ship our own files (the four dylibs built from `engine/`, the canary
app built from `canary/`, `engine/profiles/cfg-m10.plist`, `fixtures/media/qr.png`, `restore-rules/*.json`, this file and
`LICENSE`) and the CLI binary, which statically links the Go runtime and standard library (notice below; the CLI has no
other dependencies). None of the other third-party files below are in the packages.

## Code from other camera tools: none

No file or fragment in the shipped tree is copied from serve-sim, baguette, idb, SimulatorCamera, SimCam or any other
simulator camera tool. Their issue trackers and designs informed the design, but the
engine, loader, stub, CLI, canary, scripts and tools are written from scratch. Names of other tools in the code (for
example `serve-sim` paths in `cli/internal/arm/arm_test.go`, `idb` in `engine/loader/loader.c`) are test data or
detection of those tools, not their code.

Software Mansion SimCam, sim-cli and the other unlicensed or closed projects have contributed
nothing.

## Dependencies fetched at build time

The fixtures' npm packages, CocoaPods and pub packages (react-native-vision-camera, expo-camera, Flutter `camera`,
`mobile_scanner` and their dependencies) are not in the repo; the lockfiles above pin them and the package managers fetch
them, each under its own licence. stuntcam's engine, loader, stub and CLI link only Apple's system frameworks and the Go
standard library (`cli/go.mod` has no `require`).
